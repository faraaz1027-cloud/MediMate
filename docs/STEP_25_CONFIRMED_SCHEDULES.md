## Prioritized findings and resulting behavior

1. Confirmed A1 instructions had no A2 storage or UI. Add source selection, source review, full-course preview, separate explicit confirmation, saved schedules/versions/events and patient-scoped reads. Unconfirmed, incomplete, foreign, archived or mismatched references fail before activation. Quantity/unit come from A1; strength remains separate text. Arbitrary prescription prose is never automatically interpreted.
2. Naive local-time arithmetic would mishandle DST and day boundaries. Use pinned `@js-temporal/polyfill` 0.5.1, with reject disambiguation, deterministic fixed-local versus elapsed-UTC semantics and full-course validation. [Official polyfill](https://github.com/js-temporal/temporal-polyfill/tree/v0.5.1), [Temporal timezone behavior](https://tc39.es/proposal-temporal/docs/timezone.html). A named timezone cannot prove clinical timing is correct; the responsible person must clarify ambiguous source instructions.
3. A rolling seven-day horizon would need the later worker to avoid dropping day eight. Require an explicit exclusive end and persist the entire finite course, bounded to 90 elapsed days / 2000 events, atomically. Preview exposes every event; upcoming reads cover seven days. This is an explained technical contract refinement under the lab guide, not a change in function scope/ownership. Longer/indefinite courses are not supported yet. Do not invent an end from uncertain duration.
4. Preview/confirmation and later edits could race source changes or duplicate work. Hash short-lived actor/patient-bound tokens; bind source and target revision; consume once inside the domain/audit/idempotency transaction. Hidden source fences conflict with concurrent source edits/archive without changing public source revisions. Unique instruction/schedule and version/event indexes, CAS revisions and replay prevent duplicate generation. Paused schedules can receive a reviewed replacement after source change.

## Behavior and limits

- New/replacement previews require schedule.write, prescription.read and cabinet.read. Confirm/resume recheck source permissions/status in the transaction; pause requires schedule.write. Reads expose retained schedule snapshots under schedule.read, without granting access to the full source charts.
- New source must be current confirmed A1, complete and not flagged for clarification. Linked cabinet ID must match; otherwise the reviewer explicitly selects an active same-patient item. No clinical product matching or strength conversion. Positive quantity/unit must match A1 exactly, allowing equivalent decimal formatting. The human review checkbox is an acknowledgement, not a semantic parser or clinician approval.
- Start inclusive, end exclusive; explicit future UTC endpoints ending in Z. Fixed HH:mm times track the saved timezone and reject overlaps/gaps anywhere in the course. Interval minutes track elapsed UTC time from an explicit anchor at/before start. No conditional/as-needed mode. Technical bounds do not prescribe duration.
- Confirmation stores immutable source/rule snapshots and all occurrences. One schedule per current instruction prevents accidental duplicates; edit the existing schedule. This is not clinical deduplication across different prescriptions/medicines.
- Replacement cancels only pending old events at/after the future boundary, including events beyond the new end. It retains old events before that boundary and all past/taken/skipped rows. Every event retains its own timezone and dose snapshots. Old versions are immutable.
- Pause cancels pending future events across versions. Resume restores this version's original rows cancelled by pause, at/after the explicit future resume time (at least current version start), before its original end. It never restores replaced/acted/elapsed rows or inserts a duplicate. An altered/archived source blocks resume; correct/reconfirm A1 or cabinet, then preview a reviewed replacement of the paused schedule. New source confirmations never silently retime an existing schedule.
- No reminder delivery, taken/skipped/snooze action, stock effect, daily extension worker, deployment or real Telegram test is claimed. Historical pending events remain unconfirmed. C2 and worker reconciliation remain Steps 27–28. Existing Module 1 live Telegram gate is still open because no bot/test recipient exists.
