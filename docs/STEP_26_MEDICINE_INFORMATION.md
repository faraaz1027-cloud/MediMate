## Provider and applicability decisions

Use the [official openFDA drug-label endpoint](https://open.fda.gov/apis/drug/label/how-to-use-the-endpoint/) and [documented label fields](https://open.fda.gov/apis/drug/label/searchable-fields/). Search only the numeric RxCUI from a saved selected RxNorm clinical/branded product. Only numeric product IDs and validated label UUIDs go upstream; never patient IDs/names, notes, cookies, access grants or arbitrary URLs. openFDA's [product annotations](https://open.fda.gov/apis/drug/label/understanding-the-api-results/) provide candidate identifiers, not proof that a physical package matches. Its data is not a medical-care decision service.

An eligible candidate needs record UUID, set UUID, numeric version, provider effective-date field, an exact matching RxCUI, product name metadata and at least one usable original passage. Show brand/generic names, manufacturer, route and NDC when supplied. The responsible reviewer must inspect actual product/ingredient/strength/form applicability and clarify discrepancies. No semantic strength conversion, clinical matching, prescribing advice, dose change, ingredient confirmation, interaction checking or AI-generated summary is implemented. US label coverage may not cover a local/Bangladesh product; unavailable is an honest outcome.

Display whitelisted sections when present: active_ingredient, dosage_forms_and_strengths, purpose, indications_and_usage, boxed_warning, contraindications, warnings, warnings_and_cautions, storage_and_handling. Keep each included array element's original text and index; render as escaped text with whitespace preserved, never execute HTML. Missing sections are not evidence of no risk. Link to the full exact API record by immutable ID; set ID/version/effective date remain visible metadata. Original source text is distinct from the private editable note.

Bounded adapter: HTTPS fixed host/path, no redirects, eight-second fetch timeout, four-MiB body cap, at most 20 queued requests, 300-ms request spacing, 100-entry/12-hour public search cache, per-process 500-attempt UTC-day budget and one-minute cooldown after 429. Candidate pages are five raw records, at most the newest 105. Explicit refresh bypasses search cache; successful first-time selection always refetches its exact record. Cached retrieval time stays the original retrieval time. A valid provider no-match is empty/unavailable; timeouts, rate limits, invalid JSON/shape and unexpected HTTP responses are 503 errors. No secret/API key or new dependency is required for this demonstrated anonymous path. [Current official limits](https://open.fda.gov/apis/authentication/) are shared by IP; this local guard is not a distributed quota across processes/restarts. Higher usage needs a separately reviewed configuration.

## Storage, API and interface

`MedicineCard` is unique per patient+cabinet item, with availability, optional source pointer, original selectedPassages, private personalNote, item snapshot/revision, source-review actor/time and a revision for CAS. SourceRecord gains optional sourceVersion. Each successful new selection creates an immutable public retrieval receipt; replay reuses the original response. Global provider/ID/hash deduplication was deliberately not added: separate retrieval receipts retain their own times. No destructive migration/backfill or fake historical sources are created.

GET candidates requires cabinet.read; GET card requires cabinet.read and no network. PUT selection/removal and PATCH note require cabinet.write, CSRF and a UUID idempotency key. First write uses expectedRevision:null; later writes use the current integer. Selection also supplies expectedCabinetRevision, expectedContentHash and applicabilityConfirmed:true. PUT with selectedLabelId:null explicitly removes current evidence while keeping notes and old public receipts. A note can be saved without a label, or cleared with an empty string. Archived cabinet items are readable, with searches/writes blocked. Later cabinet edits expose itemChanged instead of silently relabelling the retained evidence. Full contracts and error distinctions are in Step 16.
